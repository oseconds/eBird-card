== Why?

Birders often share their GitHub profile as a personal portfolio, but there is currently no simple way to showcase recent eBird activity directly inside a README.

While the official eBird API provides rich observation data, it intentionally does not expose every user-oriented view required for a GitHub profile widget.

**eBird-readme-card** bridges that gap.

Instead of replacing the official API, it combines publicly available profile information with official eBird endpoints to generate a clean, automatically updated SVG card.

Every day, GitHub Actions refreshes the card and commits the newest version back to your repository.

The result is a lightweight widget that behaves similarly to projects such as:

* github-readme-stats
* waka-readme-stats
* spotify-github-profile

but for birding.

== Features

* ✨ Beautiful SVG card designed for GitHub Dark Mode
* 🐦 Recent observations from your public eBird profile
* 🔗 Official eBird API enrichment
* 🎨 Jinja2-based SVG template system
* 🤖 Fully automated with GitHub Actions
* 🔒 Credentials stored using GitHub Secrets
* ⚡ Fast static SVG generation
* 📦 Planned reusable GitHub Action

[source,yaml]
----
- uses: oseconds/eBird-readme-card@v1

  with:
    ebird_user_id: ${{ secrets.EBIRD_USER_ID }}
    ebird_api_key: ${{ secrets.EBIRD_API_KEY }}
----

== Why Jinja2?

Instead of building SVG with string concatenation, the project uses Jinja2 templates so the SVG layout stays readable while Python only supplies data.
